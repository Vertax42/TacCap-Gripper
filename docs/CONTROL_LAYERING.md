# 夹爪控制分层设计(提案)

> 固件与 SDK 的职责应该按**反应延迟**划分,而不是按实现方便划分。
> 安全包络必须放在丢一个包也不会失效的地方;主机只负责意图。

适用:从爪固件 1.1.5 · EduLite05(额定 1.8 Nm / 峰值 6.0 Nm)
证据:2026-08-27 在 `TCGU01A28Z0018s`(行程 1.2076 rad,Reverse)上的实测
固件参考:`tc-gu-01 @ 8f03cd2`,协议镜像漂移检查通过(66/66)

标注约定:**[实测]** 当天硬件直接测到 · **[推算]** 由实测外推 · **[未验证]** 已实现但未在硬件上触发过。

---

## 1. 今天测到了什么

| 观测 | 数值 | 含义 |
|---|---|---|
| 1.1.5 的 MIT 路径堵转保护 **[实测]** | 无 | `can_motor_gripper_stop_on_limit_stall()` 只在速度命令路径被调用,且只管行程末端。阻抗命令下唯一兜底是电机自己的 `0x700B` |
| 阻抗阶跃目标的冲击速度 **[实测]** | 8.68 rad/s | 是力位混合闭合速度(0.5)的 17 倍。阻抗环没有任何速率限制 |
| 撞上刚性物体后力矩爬升 **[实测]** | 0.03 → 2.41 Nm / 20 ms | 仍在上升时被看门狗中止。平台值 **[推算]** ≈4.96 Nm = kp·误差 |
| 穿过松动物体时的力矩 **[实测]** | < 0.03 Nm | 以 5.5 rad/s 掠过物体位置,力矩**完全没起来**就把它打飞了 |
| 堵转时命令 vs 反馈力矩 **[实测]** | 0.359 → 0.213(0.59) | 主机算出的力矩不是电机给出的力矩 |
| 自由行程的分离余量 **[实测]** | \|v\| ≥ 0.183 rad/s | 同段 \|τ\| ≤ 0.142;止点 \|v\|≈0.012、\|τ\|≈0.21。**速度是干净的分离量,力矩不是** |
| 主机在控制时轮询状态 **[实测]** | ACK 超时 | 相位锁只保护遥测,不保护 ACK。**控制期间主机读不了任何需要应答的量** |

## 2. 原则:权限跟着延迟走

主机链路是 100 Hz、相位锁,且控制期间不能轮询。这给主机侧保护设了反应下限:
检测要几个状态帧,确认要几十毫秒。**30 ms 内,8 rad/s 的夹爪走过 0.24 rad。**

这就是为什么主机侧堵转保护需要 60 ms 确认窗、触发时力矩已冲到 2.7 Nm;
也是为什么物体一旦能被打飞,后面所有基于力矩的保护都没有机会。

> **安全包络属于固件,主机拥有意图。** 主机侧力矩上限本质上是在一条会丢包、
> 不能查询、有几十毫秒延迟的链路上做实时保护 —— 可作过渡,不可作设计。

## 3. 建议的三层划分

三层是真实的权限层级:每一层都能否决它上面那层。

**电机(内部环)—— 最终包络,主机和 MCU 都绕不过**
- `0x700B` 力矩上限、`0x7018` 相电流上限
- `0x7028` CAN 命令超时:MCU 完全停摆时也会丢弃过期命令

**固件(500 Hz)—— 安全包络 + 接触判定,权威层**
- 每周期钳位:力矩(连续/峰值 + I²t)、速度、位置限、命令超时
- 接触判定 —— 它已有验证过的 `task_canmotor_is_stalled()` 和每台设备的自标定参数
- 状态机 `IDLE / TRACK / CONTACT / GRASP / HOLD / FAULT`
- 上报:当前状态、哪条包络在起作用、故障原因

**SDK(100 Hz)—— 意图与标定,不实现自己来不及执行的安全逻辑**
- 选模式、给设定值;在固件允许的上限内选包络**数值**
- 归一化位置映射、标定记录管理
- 可观测性:日志、诊断、轨迹回放

**关键接口变化**:今天固件有四类互不相干的运动命令,保护只挂在其中一类上 ——
这正是漏洞来源。建议收敛成**一个命令面:模式 + 设定值 + 包络**,包络永远存在,不随模式消失。

## 4. 四种控制模式的落法

| 模式 | 主机发送 | 固件执行 | 今天缺什么 |
|---|---|---|---|
| **位置** | 目标位置 + 最大速度 + 最大力矩 | 带速度/加速度限的轨迹,每周期力矩钳位 | SDK 用阻抗假装位置控制,没有速度限 —— 就是那个 8.68 rad/s 猛冲 |
| **阻抗** | 目标位置、kp、kd、τ_ff + 力矩包络 | `τ = clamp(kp·e + kd·(v_ff−v) + τ_ff, 包络)` | 那个 `clamp` 不存在。且必须作用在**反馈电流**上,不是算出来的值(比值 0.59) |
| **力** | 目标力矩 + 位置软限 | 纯 τ_ff,kp=kd=0,到软限则退化为位置保持 | `set_torque` 无位置保护 —— 空载会一路加速 |
| **力位混合** | 目标位置 + 夹持力矩 + 接近速度 | 速度阻尼接近 → 接触判定 → kp=kd=0 力矩保持 | 现在在 SDK 侧 100 Hz(已验证),应下沉到固件 500 Hz |

## 5. 一个必须先讲清楚的坑

归一化位置 `0.0` **不是几何硬止点**。开机自标定用*速度命令*顶到
`close_stall_torque_nm`(默认 0.35 Nm)堵转,后退 0.120 rad,再回到该点,
然后在**带载使能状态下**设零 —— 预压是烧进零点定义里的。

而 kd 形式的 MIT 帧发不出同样的推力,实测停在 0.0167 归一化,**差 0.020 rad**。
`set_target(0.0)` 在这个控制模式下是**够不到的点**,加任何到达容差都无效。

> 标定用的力和控制用的力必须是**同一套包络下的同一个量**,否则位置定义和位置控制永远对不上。

## 6. 过渡:今天 SDK 侧已实现的三层

1.1.5 固件在 MIT 路径上没有保护,所以今天主机必须扛。这是权宜之计。

| 层 | 机制 | 实测效果 | 目标归属 |
|---|---|---|---|
| ① 误差钳位 | 命令目标钳在实测位置 ±`max_position_torque_nm/kp` 内 **[实测]** | 8.68 → 1.60 rad/s;2.724 → 0.145 Nm | 固件包络(速度+力矩) |
| ② 力矩天花板 | 反馈力矩越限则切 kp=kd=0 纯 τ_ff 保持 **[未验证]** | 至今未在硬件上触发过 | 固件包络(每周期) |
| ③ 堵转钳位 | 确认堵转后把目标钳在夹爪实际停住的位置 **[实测]** | 触发 1.458 Nm,随后稳定 0.051 Nm | 可留在 SDK(是体验,不是安全) |

三层叠加实测:峰值 1.458 Nm,触发后持续 0.051 Nm,温度 32.0 °C 全程不动,
物体既没被弹飞也没被压穿,反向下发目标可干净解除。对比无保护的 ≈4.96 Nm 平台,
**持续力矩相差约 100 倍**。

> **①是不可省的那一层。** 关掉①之后②和③都拿不到触发机会 —— 当天重复出现三次:
> 夹爪以 5.5 rad/s 掠过物体,力矩没升起来就把它打飞了。
> **任何基于力矩的保护,都要先有一层把接近速度压下来。** 这对固件侧实现同样成立。

## 7. 需要决定的事(按优先级)

1. **包络下沉到固件**。四类命令收敛成一个命令面,包络不随模式消失。全部提案里唯一真正重要的一条。
2. **接近速度是包络的一部分**,不是模式的属性。位置和阻抗模式都必须能被限速。
3. **接触判定归固件**。参数已按设备存在固件里,500 Hz 也比 100 Hz 合适。
4. **标定力与控制力统一**,否则位置 0.0 永远够不到。
5. SDK 保留:模式选择、设定值、包络数值、归一化映射、可观测性。
